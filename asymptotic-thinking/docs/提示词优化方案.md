## 一、概述

### 扩展定位

`agent/extensions/asymptotic-thinking` 是 pi-agent 内置扩展，通过五态状态机引导 AI 进行结构化、分阶段的深度推理。支持 6 大任务类型 × 27 子类型 × 6 级难度的自适应提示词注入。

### 核心机制

| 机制 | 说明 |
|:--|:--|
| 五态流转 | IDLE → DEEP_UNDERSTAND → DESIGN → EXECUTE → VERIFY → IDLE |
| 三层提示词 | 第1层通用指令 + 第2层大类型指令 + 第3层细分领域指令 |
| 轮次控制 | 每状态有最大轮次上限，超限触发硬警告强制流转 |
| 开关控制 | `/asymptotic-toggle` 按 session 隔离，默认启用 |

### 三个工具

| 工具 | 用途 |
|:--|:--|
| `asymptotic-think_set-task-info` | 设定任务画像（难度、大类型、子类型） |
| `asymptotic-think_transition` | 状态流转 |
| `asymptotic-think_status` | 查询当前状态机位置 |

## 二、提示词架构

### 三层模型

```
buildTemplate(state, turn, master, sub, diff)
│
├─ 第1层 通用指令（硬编码在 templates.ts）
│   └─ 5 状态 × (instruction + actions + constraints)
│   └─ 所有场景共享，定义状态语义和流转规则
│
├─ 第2层 大类型指令（MASTER_TASK_HINTS）
│   └─ 6 大类型各一条 hint，以引用块形式注入 instruction
│   └─ 定义该大类型的通用思维框架
│
└─ 第3层 细分领域指令（src/prompts/{master}/{sub}.ts）
    └─ 27 子类型 × 4 状态（DEEP_UNDERSTAND/DESIGN/EXECUTE/VERIFY）
    └─ 仅输出该领域独有的增量指令
```

### 组装逻辑

```
第1层 instruction（角色定义 + 状态行 + 评估指引）
    ↓ 叠加
第2层 hint（> 引用块，大类型思维框架）
    ↓ 叠加
第3层 promptContent（领域增量，从 .ts 模块动态加载）
```

### 标签语义

| 标签 | 语义 | 内容 |
|:--|:--|:--|
| `<instruction>` | 宏观指导 | 角色定义 + 状态行 + 任务描述 + 思考方向 + 领域提示词 |
| `<actions>` | 具体执行 | 加载 skill 指南 + 操作步骤 + 流转指令 |
| `<constraints>` | 纯限制条件 | 如"只读"、"不执行修改"，不含流转类条目 |
| `<output>` | 输出模板 | 仅 VERIFY 状态，提供检查表格式 |

## 三、五态状态机

### 状态行格式

```
第{N}/{M}轮 {状态标签}阶段 · {任务描述}
```

示例：`第1/1轮 深度理解阶段 · 编程类-Java开发 · 微不足道`

### IDLE 状态

```xml
<task{N}>
<instruction spec="markdown">
严格遵守人格角色定义
第1/0轮 空闲阶段

评估是否需要使用记忆系统（mempal skill）、网络搜索（web_search）、网页获取（web-fetch），必须给出评估结论。
深入分析用户指令的任务类型和难度，为后续阶段做准备。
</instruction>

<actions spec="markdown">
- 使用 skill 工具加载 asymptotic-thinking 技能指南，严格遵守其中定义的完整工作流程
- 调用 `asymptotic-think_set-task-info` 工具设定任务画像
</actions>
</task{N}>
```

### DEEP_UNDERSTAND 状态

```xml
<task{N}>
<instruction spec="markdown">
严格遵守人格角色定义
第{N}/{M}轮 深度理解阶段 · {任务描述}

> {大类型 hint}

{第3层领域提示词}
</instruction>

<actions spec="markdown">
- 使用 skill 工具加载 asymptotic-thinking 技能指南，严格遵守其中定义的完整工作流程
- 逐条列出需求的功能边界、约束条件和验收标准
- 缺失信息用工具检索补齐，不猜测
- 完成分析后调用 `asymptotic-think_transition` 流转 DESIGN
</actions>

<constraints spec="markdown">
- 只读文件辅助理解，不执行写操作
</constraints>
</task{N}>
```

### DESIGN 状态

```xml
<task{N}>
<instruction spec="markdown">
严格遵守人格角色定义
第{N}/{M}轮 方案设计阶段 · {任务描述}

> {大类型 hint}

{第3层领域提示词}
</instruction>

<actions spec="markdown">
- 使用 skill 工具加载 asymptotic-thinking 技能指南，严格遵守其中定义的完整工作流程
- 方案按顺序列出：涉及文件 → 前置步骤 → 实施路径 → 验收标准
- 每个步骤写明具体工具名和文件路径
- 完成后调用 `asymptotic-think_transition` 流转 EXECUTE
</actions>

<constraints spec="markdown">
- 设计完成前不执行任何代码修改
</constraints>
</task{N}>
```

### EXECUTE 状态

```xml
<task{N}>
<instruction spec="markdown">
严格遵守人格角色定义
第{N}/{M}轮 执行阶段 · {任务描述}

> {大类型 hint}

{第3层领域提示词（已剥离 transition 语句）}
</instruction>

<actions spec="markdown">
- 使用 skill 工具加载 asymptotic-thinking 技能指南，严格遵守其中定义的完整工作流程
- 严格按方案步骤顺序执行
- 每步执行后自检结果，确认通过再推进下一步
- 方案不可行时回退 DESIGN 重新设计
- 全部步骤完成后调用 `asymptotic-think_transition` 流转 VERIFY
</actions>
</task{N}>
```

### VERIFY 状态

```xml
<task{N}>
<instruction spec="markdown">
严格遵守人格角色定义
第{N}/{M}轮 自检验证阶段 · {任务描述}

> {大类型 hint}

{第3层领域提示词}
</instruction>

<output spec="markdown">
| 维度 | 状态 | 说明 |
|:--|:--:|:--|
| 需求理解正确完整 | ✅/❌ | ... |
| 实施步骤全部完成 | ✅/❌ | ... |
| 输出格式符合规范 | ✅/❌ | ... |
</output>

<actions spec="markdown">
- 使用 skill 工具加载 asymptotic-thinking 技能指南，严格遵守其中定义的完整工作流程
- 逐项如实标注 ✅ 或 ❌
- 有 ❌ 项修正后全部重新验证
- 全部 ✅ 后调用 `asymptotic-think_transition` 流转 IDLE
</actions>
</task{N}>
```

### 难度×状态轮次上限

| 难度 | DEEP_UNDERSTAND | DESIGN | EXECUTE | VERIFY |
|:--|:--:|:--:|:--:|:--:|
| TRIVIAL | 200 | 100 | 500 | 100 |
| SIMPLE | 500 | 300 | 1500 | 300 |
| MODERATE | 1500 | 1000 | 4000 | 1000 |
| COMPLEX | 3000 | 2000 | 7000 | 2000 |
| HARD | 5000 | 3500 | 9000 | 3000 |
| EXTREME | 7000 | 5000 | 10000 | 4000 |

超限触发硬警告：`🚨 严重警告：你已在【XX】状态停留 N 轮，严重超时！立刻调用 asymptotic-think_transition 流转！`

## 五、事件钩子

### before_agent_start

每轮对话开始前触发，向 LLM 注入当前状态机的引导提示词。

- IDLE 状态：注入完整 `<task{N}>` 标签（instruction + actions）
- 非 IDLE 状态：注入完整 `<task{N}>` 标签 + 续作提醒（防止 LLM 被新消息打断）

```typescript
const finalGuideText = isIdle
  ? guideText
  : `${guideText}\n\n> ⚠️ 上一次对话未完成任务，不可中断——请回到当前【${label}】状态，继续把未完成的流程推进到底。\n严格遵守人格角色定义，严格遵守用户指令。`;
```

### turn_end

每轮对话结束时触发，递增轮次计数。IDLE 状态不处理（before_agent_start 已注入完整引导）。

## 六、关键设计决策

| 决策 | 说明 |
|:--|:--|
| `<task{N}>` 标签无属性 | role/desc/task_status 移入 instruction 内部文本，减少属性噪音；N 为任务轮次，隔离不同任务提示词 |
| 状态行含任务描述 | `第1/3轮 执行阶段 · 编程类-Java开发 · 微不足道`，一条线承载全部元信息 |
| transition 统一由 actions 管理 | 第3层 prompt 模块中的 transition 语句在组装时剥离，避免与 actions 重复 |
| 评估不强制调用 | IDLE 阶段评估检索需求，必须给出结论但不强制调用（简单任务省 token） |
| skill 指南引用 | 每个状态的 actions 首行强制加载 asymptotic-thinking skill 指南 |
| constraints 仅限纯限制 | 流转类条目归入 actions，constraints 只保留"只读""不修改"等硬约束 |
| 开关按 session 隔离 | `/asymptotic-toggle` 写入 SQLite 表 `asymptotic_thinking_toggle`，默认启用 |
